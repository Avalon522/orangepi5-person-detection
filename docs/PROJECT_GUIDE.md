# 项目复刻流程与知识总结

## 1. 环境盘点
确认板卡、系统、架构、内核、内存、磁盘、Python、摄像头节点和网络。实际为 Orange Pi 5 / RK3588S / 8GB，Ubuntu 22.04.5、6.1.99-rockchip-rk3588、aarch64、Python 3.10.12。

## 2. 摄像头采集
摄像头使用 uvcvideo；video0 为图像采集，video1 为元数据。以 MJPG 640×480 请求 30FPS，用 OpenCV 读取 60 帧并保存图片，60/60 成功。采集帧率不等于模型处理帧率。

## 3. NPU 验证
驱动 0.9.8，Runtime 2.3.0，Lite2 2.3.0。官方 ResNet18 RK3588 模型成功分类航天飞机，分数 0.999680。系统自带旧 rknn_demo 缺少共享库，未通过替换驱动解决，而是转用 Lite2 官方示例。

## 4. 模型准备
电脑 WSL2 Ubuntu 22.04、x86_64、Python 3.10.12，安装 Toolkit2 2.3.0。官方适配 YOLOv8n ONNX 输入 [1,3,640,640]，三种尺度 80、40、20，各输出位置编码、80 类分数及辅助分数。不是普通单输出 YOLO 后处理。

## 5. 模型转换
使用 rk3588 / fp 参数，不进行 INT8 量化，也不需要校准图片。ONNX mapping 接口错误通过固定 onnx==1.16.1 修复。保留环境锁定、模型哈希和转换日志。

## 6. 静态推理
保持比例缩放、补边至 640 方形，BGR 转 RGB。RKNN 已设置除以 255 的归一化，不在板端重复除以 255。DFL 解码 64 个位置通道，筛选人员并 NMS，最后还原到原图坐标。公交车测试图检测 4 人，用户确认框正常。

## 7. 连续检测
NPU 与摄像头只初始化一次，循环采集与推理，退出释放资源。摄像头原始画面与模型输入分辨率不同，需保持一致的补边和坐标逆变换。

## 8. 网络接收
最初开发板接光猫、电脑连下级路由器，不宜假设双向连通。将开发板接路由器 LAN 口后，两端同一网段。电脑运行 Python 标准库 HTTP 服务。

## 9. 报警与网页
早期版本连续 3 帧 + 10 秒冷却。最终版本改为每次进入仅一次历史事件，连续约 1 秒无人员才能重新布防；大屏实时画面与历史记录分离。报警分数阈值 0.5，画框阈值 0.25，因此画框数量可能多于有效人员数。网页实时人数反映当前帧，进入事件判定带防抖，二者时间粒度不同。

## 10. 整理与验收
本资料归档实际运行文件、转换环境、校验值及记录。用户初期暂时跳过，后于 2026-11-23 确认已完成 30 分钟连续运行测试且运行正常。后续应补测长期内存、相机断流、电脑服务中断、重启恢复及网络延迟。

## 三类工具的职责
Toolkit2 在电脑转换模型；Lite2 在开发板提供 Python 调用；Runtime 与内核驱动协作执行 NPU 运算。版本一致是验证起点，最终仍必须做实际推理验证。
